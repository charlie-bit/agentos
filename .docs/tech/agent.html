1 定位与边界

AgentOS 是可插拔的 Agent 执行框架，不是商业插件平台，也不是多租户 SaaS。 产品形态是单进程、单机、一个数据目录（spec #134/#178）。

维度承诺依据
运行时主 runtime 可换；当前内核由 @anthropic-ai/claude-agent-sdk 适配（packages/adapters/claude-sdk），跨运行时验收未完成#144 / #298 未建面
部署一个进程、一个 .agentos/ 数据目录；无 K8s / ArgoCD / ingress 产品化#134 / #178 边界
多 Pod不支持；ledger 是嵌入式 node:sqlite，同会话多进程无协调#132 纪律 边界
密钥manifest 只允许 env 变量名；内联凭证 schema 直接拒绝#12 已实现
配置写 API不做；配置面 = yml + git，Web 只读 + validate 触发#183 边界
可视化编排器不做；只读渲染 + 单击实例化，编辑 = 改 yml#196 / #440 边界
对等 Agent 协议不做 A2A 内核化；外部 agent 唯一路径 = MCP 工具 manifest#199 / #418 边界

职责切分

层职责代码位置
Contracts类型与不变量；跨边界只用 JSON Schemapackages/contracts/src/
Coremanifest 加载/校验、tool plan、ledger、路由、治理、workflow 引擎packages/core/src/
Adapters唯一允许 import kernel SDK 的地方；把中立 plan 翻译成内核原生形状packages/adapters/claude-sdk/
Providersmodel-* / knowledge-* / entry-* 的具体实现packages/providers/ · packages/entry/
Composition root装配：加载配置 → 校验 → 挂载 → 起服务cli/src/serve.ts
干净的接缝：core 不 import 任何 kernel；adapter 是唯一的 SDK 边界； provider 只依赖 contracts。这就是"换 runtime 不改上层"的物理保证。

3 四层插件模型

flowchart LR M["Manifest
yml 声明 WHERE"] --> C["Contract
版本化接口"] C --> L["Loader
实例化 · 校验 · 展开"] L --> R["Registry
运行时查询"] P["preset"] -.->|只做名字引用| M
层做什么不做什么
Manifest声明服务器在哪、用什么凭证名、哪些工具、是否幂等不定义工具本体（MCP 在运行时发现）
Contract冻结"一个 law"——例如知识 provider 只返回结构，不返回渲染文本不关心实现语言/进程
Loaderkind 分发、引用完整性、${VAR} 展开、失败分类不注册、不打印、不挂载
Registry运行时按名字查已挂载 provider不做配置判断

preset 是唯一收敛点

kind: preset
version: "1"
name: my-agent
knowledge: local-markdown      # 名字引用
model: deepseek
tools: [mcp-filesystem, slack] # 挂载顺序即此处顺序
entry: cli
# 可选（additive）：
channels: { web: rest }        # 频道 → 入口适配器
channelModels: { cli: deepseek }
budgetUsd: 5
maxConcurrentSessions: 2
agents: [triage-analyst]       # 第五层引用
workflows: [daily-triage]      # 第六层引用
preset 里出现任何内联配置或凭证，schema 层直接拒绝；工具名必须能在 config 树中找到， 否则 preset validate 非零退出。

4 契约层

插座接口文件唯一法则
KnowledgeKnowledgeProvider 六动词knowledge.ts只出结构不出文本；draft 在 commit 前不可见
ToolToolProviderManifest + ToolMountPlantool.tsmanifest 说 WHERE，MCP 说 WHAT；跨接缝只走 JSON Schema
ModelModelProviderManifest + ModelDialectmodel.tsalias 即租约；凭证是 env 变量名
EntryEntryAdapter 四动词 + TranscriptEntryentry.tsconfirm:false 合法，核心自动把知识写降为只读

横切类型

Preset
四层名字引用 + channels / channelModels / budgetUsd / maxConcurrentSessions
NeutralTool
core 发出的进程内工具形状；adapter 负责翻译。JSON Schema 进，JSON data 出
TranscriptEntry
最小可重放集：role / text / toolName / isError / timestampMs / event
Session key
web- 前缀：浏览器会话 ↔ ledger 行的约定
版本策略：additive-only。新增字段不破坏消费者；改变语义 = major bump + spec 修订记录。 TranscriptEntry.event 就是 additive 的示例——不认识该值的消费者按原样渲染。

5 一轮 turn 的生命周期

sequenceDiagram participant E as Entry（cli/rest） participant S as serve 装配根 participant A as Adapter participant K as Kernel participant L as Ledger E->>S: POST /api/chat 或 REPL prompt S->>L: getByExternalKey / createSession S->>S: 解析角色链 · 模型路由 · 工具围栏 S->>A: plansToMcpServers + 预批准列表 A->>K: query(prompt, resume, signal) K-->>E: 事件流（assistant.text / tool.progress / todo.changed） K->>K: 工具调用 → 门禁（canUseTool）→ 执行 K->>L: markStatus(running → idle) · 用量归因 E-->>E: SSE 帧 / 终端输出

关键不变量

不变量实现代码
turn 状态在 DB 不在内存每轮开始 markStatus running，结束落 idle；侧栏读 DBcore/session/ledger.ts
恢复来自存储的历史resumeSdkSessionId 从 ledger 行读取，不从内存 emitter 重放cli/src/serve.ts
大结果落盘>10KB 的工具结果写入工作区 tool-results/，模型拿指针core/governance/offload.ts
非幂等工具不自动重试执行器按 ToolMountPlan.idempotent 分支core/loader/retry.ts
预算门禁累计 usage.log 成本越过 budgetUsd，下一轮先问人cli/src/serve.ts
并发上限maxConcurrentSessions，超出 FIFO 排队而非失败cli/src/concurrency.ts
中止全链路AbortController 从入口传到内核；workflow 实例也可被中止（#365）serve.ts / workflow/runner.ts
崩溃恢复启动时 sweepRunning() 把遗留 running 行标为 abortedledger.ts

失败分类（可行动卡片）

结果 payload 带 subtype：tool-missing / gate-denied / model-fallback / network。入口按四类渲染独立卡片，而不是一条红杠（#264）。

6 三个 Provider 插座

6.1 ModelProvider

概念说明
Manifestconfig/models/*.yml：provider + baseUrlEnv + credentialsEnv + alias 表
Dialect厂商方言实现，tag ∈ anthropic-compat | bedrock | openai-compat
Alias leasealias（general/reasoner）映射到具体 model id；fallbackChain 只能引用本 manifest 内的 alias
路由优先级请求覆盖 > channelModels（频道/租户）> preset 的 model 槽
健康与回落dialect healthCheck(lease, {env})；主 manifest 全 alias 不健康时走 fallbackModels（跨端点，显式声明）
归因usage.log 逐轮记录 model/cost/tenant/agent
# config/models/deepseek.yml —— 是租约，不是代码
kind: model
version: "1"
name: deepseek
provider: deepseek
baseUrlEnv: AGENTOS_DEEPSEEK_ANTHROPIC_BASE_URL   # 变量名，不是 URL
credentialsEnv: AGENTOS_DEEPSEEK_API_KEY
models: { general: deepseek-chat, reasoner: deepseek-reasoner }
fallbackChain: [general]

6.2 ToolProvider（MCP）

一个工具服务器 = 一条声明式注册项；工具定义在运行时通过 MCP tools/list 发现，绝不写进配置。

字段语义失败行为
transportsdk / stdio / http（discriminated union，多余字段拒绝）schema 错误 = fail loud
command / endpointstdio 命令行（无 shell 解释）/ http URL；支持 ${VAR}缺变量 = environment 错误 → 单 provider 降级 ⚠
authnone / bearer-token-env / header-env；只给变量名租约不可解析 → 同一降级路径
allowedTools白名单；缺席 = 挂载全部发现工具（drift 标未验证）启动期 drift 检查
idempotent默认值 + 按工具名覆盖；未声明 = 永不自动重试执行器分支
envRouting限定可挂载的环境标签；缺席 = 所有环境不匹配 = 警告 + 不挂载
enabledfalse = 声明但不挂载，保留 diff 可见性装载期过滤
sandboxfsRoots + network.allow；adapter 只授予声明根未声明 = sandbox-unverified
drift 检查是测谎仪：声明了 allowedTools 就必须镜像 server 的真实工具集。 宁可缺席（让 drift 报未验证），也不要写一份会过期的假名单。

6.3 KnowledgeProvider

动词语义
bootstrap目录索引 + 最近更新（注入用）
search返回 SearchHit[]；无命中返回 []，不抛错
getPage原文内容
listPages索引列表（当前无生产调用方，契约保留）
writePage两阶段：只写 draft，未 commit 对 search 不可见
commit确认后落库并记账

默认实现 @agentos/knowledge-markdown：path / submodule / git-sync 三种挂载； 页面 frontmatter 支持 owner / last_verified / stale_after / status。规模甜蜜点是几十到几百份 md，不做 RAG。

7 编排面：角色 / Workflow / Project / Todo

7.1 Agent 角色（config/agents/*.yml）

kind: agent
version: "1"
name: triage-analyst
baseAgent: docs-writer        # 可选：继承另一角色
systemPrompt: |
  ...
tools: [slack_search_channels, todo_add]   # 运行时工具名白名单
knowledge: local-markdown
model: deepseek
规则语义
继承systemPrompt 拼接（base 在前，冲突时 child 覆盖）；tools/knowledge/model 并集，child 覆盖同名
循环/悬空validate 期拒绝（环、指向不存在的角色/工具/知识/模型）
工具围栏角色 tools = 该 turn 的白名单，内核侧 canUseTool 硬执行；越界调用被拒并落审计
"自己"无 agent 参数的 turn = 主内核 preset 行为，零回归；Web 默认选中"自己"
归因transcript / usage / 审计携带 agent 标签；会话可回放角色上下文

7.2 Workflow（config/workflows/*.yml）

步骤型载荷
agent{ agent, prompt } —— 跑一个角色 turn
tool{ tool, args } —— 进程内工具
skill{ skill, prompt? } —— 经知识通道；当前无 headless runner
kb_search{ query }
review{ agent, prompt?, mustInclude? } —— 由已挂载角色裁决上一步；输出不含 APPROVE（可配置）即拒绝并停止
触发语义状态
manualWeb 按钮 / API已实现
schedulecron，分钟窗精度；无 cron 库，Node 内建调度已实现
webhooksecretEnv 指向 env 名，Bearer 校验已实现

并发上限 maxConcurrentWorkflows（#366）；中止可到达运行中的实例（#365）；每步落审计行。

Skills 挂载（stage C）：kind: skills manifest 指向一个目录，启动时扫描其中的 **/SKILL.md（frontmatter name/description），preset 用 skills: [名字] 引用。 该 manifest 与目录本身不入库（config/skills/local.yml + skills-base/ 均被 .gitignore）， 路径支持绝对路径或 ${ENV}；变量缺失只跳过该挂载并告警，不阻断启动。 skill 步骤按名字取正文作为该轮的系统提示。

输入 / 输出（stage B，additive）：category 声明主题，用于控制台分组； input.source ∈ {none, manual} —— manual 由运行端点传入，同时注入 {input} 并作为第一步的 {prev}（{input} 始终解析为原始输入）； output.sink ∈ {none, slack} —— slack 在最后一步成功后，经已挂载的 Slack 工具投递到指定 channel；投递失败会把 run 标为 error 而不是静默丢弃。Slack 拉取型输入是下一个 additive 成员。

7.3 Project

模板（config/projects/*.yml，git 管理）vs 实例（.agentos/，Web 可建可写）。 模板只声明 agents / workflows / tools / knowledge / description；实例持有标题与业务数据。 边界：配置不可从 Web 改，实例数据可以。项目仪表盘聚合待办计数。

7.4 Todo

内核不解析 MCP 结果、不内置待办领域模型（#177）。模型在对话中总结可行动项并调用 todo_add / todo_update / todo_remove / todo_list；存储在同一 sqlite 的独立表。 sourceKind ∈ {chat, mcp, manual}，sourceRef 回链到产生它的会话。 变更以 todo.changed 中立事件推送并可在回放中标记。

11 扩展指南：新增四种插件

新增 ToolProvider

  1. 在 config/tools/<name>.yml 写 manifest，匹配 ToolProviderManifest。
  2. MCP stdio/http：零代码，loader 按 transport 拉起/连接。
  3. sdk transport：实现放在 packages/adapters/**（唯一允许 kernel import 的地方）。
  4. 诚实声明 idempotent：非幂等工具按设计失去自动重试。
  5. ${VAR} 缺变量 = 硬错误，不会静默挂一个空配置。
  6. 校验：agentos preset validate；loader 行为测试：pnpm --filter @agentos/core test。
  7. allowedTools 必须镜像 server 真实工具集（离线探测），否则 drift 会报。

新增 ModelProvider

  1. 已有厂商的新 alias/端点/价格：只加 config/models/<name>.yml，零代码。
  2. 新厂商方言：实现 ModelDialect（tag + resolveChannel + healthCheck + resolveModel）于 packages/providers/model-<vendor>/。
  3. 端点与凭证只以 env 变量名进入；内联密钥 schema 拒绝。
  4. preset 的 model: 指向 manifest 名。

新增 KnowledgeProvider

  1. 实现五/六动词；返回结构不返回渲染文本。
  2. 无命中返回 []；未 commit 草稿必须不可见。
  3. 诚实声明 capabilities：write:false 必须让 kb_write/kb_commit 不进注册。
  4. 加 KnowledgeManifest；P3 一致性套件是入口闸门。

新增 EntryAdapter

  1. 实现四动词 + capabilities；confirm:false 是合法声明（核心自动只读降级）。
  2. render 遇显示故障不抛；confirm 超时是 adapter 自己的责任。
  3. preset 的 entry: 指向 adapter 名；频道路由走 channels 表。
四条通用纪律：schema 跨边界只用 JSON Schema（zod v3/v4 不兼容，跨内核传 zod 会静默丢工具）； 凭证只进 env；配置只改 yml + git；失败分环境错误与配置谎言两类—— 前者降级，后者 fail loud。
