一个进程

2 入口契约

动词语义失败约定
identity()凭证 → { userId, tenant }无法建立身份时抛错
session()客户端会话 ↔ agent 会话绑定；同一客户端会话重复调用返回同一绑定—
render(events)把中立事件推给客户端；显示故障不得抛出吞掉展示错误
confirm(req)让人类批准有后果的动作；超时视为拒绝超时是 adapter 自己的责任
capabilities.confirmfalse 合法：核心自动把知识写降级为只读注册期降级，不是运行期报错

TranscriptEntry —— 回放的最小集

interface TranscriptEntry {
  role: "user" | "assistant" | "tool";
  text: string;                 // tool 行是（可能截断的）输入
  toolName?: string;            // 仅 tool
  isError?: boolean;            // 仅 tool：调用失败
  timestampMs?: number;
  event?: "todo.changed";       // additive：待办变更可标记
}

刻意不包含：消息 id、块树、用量、推理轨迹。内核的私有存储格式不泄漏给入口。

会话主权：一个入口只属于一个内核。双内核劫持同一会话 = 上下文分裂与状态错配， 所以 channels 路由到一个与当前 serve 模式不同的适配器会在启动期被拒绝。

4 SSE 协议

sequenceDiagram participant C as 浏览器 participant R as EntryRest participant K as Kernel C->>R: POST /api/chat {sessionId, message, model?, agent?, project?} R-->>C: 200 text/event-stream R-->>C: data: {"type":"session.meta","payload":{agentSessionId,resumed}} loop 每个内核事件 K-->>R: RenderEvent R-->>C: data: {"type":"assistant.text","payload":...} end R-->>C: ": keepalive "（每 15s，注释行） C->>R: POST /api/sessions/:id/abort R-->>C: 流结束，ledger 落 idle
帧说明
data: {type, payload, timestampMs}唯一的数据帧形状；type 是点分命名空间
session.meta首帧：agentSessionId + 是否 resume
assistant.text · tool.progress增量文本 / 工具进度
todo.changed广播到所有活跃流（多标签页即时同步），不是单流事件
: keepaliveSSE 注释行，保活；reducer 不需要理解

约束

  • 每会话一路：turn 用 AbortController 注册，abort 端点命中该控制器（#216 per-session 帧路由）。
  • turn 状态在 DB：流开始 markStatus running，结束落 idle；侧栏读 DB，不读内存。
  • 断线重连：客户端重新拉 /api/sessions/:id/messages 回放，再开新流；不依赖服务端缓冲。
  • 响应头：cache-control: no-cache · connection: keep-alive · x-accel-buffering: no（防反代缓冲）。

5 鉴权与安全边界

机制行为依据
一次性 token默认开启：启动生成（或 AGENTOS_WEB_TOKEN 固定），终端打印；浏览器首次输入后存本地。--no-token / AGENTOS_WEB_NO_TOKEN=1 可显式关闭#287 / #116
token 校验开启时：x-agentos-token 头或 ?token=；缺失 = 403。关闭时：/api/* 不再校验，启动输出打警告entry-rest
绑定地址默认 127.0.0.1；容器内 0.0.0.0 是网络命名空间内部，发布由运维决定#116 / #302
路径围栏preset 校验与工作区浏览只能落在白名单目录#289 R7
日志隐私只落元数据；不落 prompt / 回复 / 工具载荷；写盘前按 env 值脱敏R2 / R9
身份内核不做 OAuth/SSO；企业身份是入口层示例#117 边界
团队服务器不是产品承诺；远程共享由部署者自加反代/VPN#173 边界
容器提醒：docker run -p 8787:8787 等于把控制台发布到宿主机所有网卡。 只想本机访问就用 -p 127.0.0.1:8787:8787。

8 部署形态

本地（常态）

pnpm install && pnpm build
node cli/main.mjs serve --web --preset config/presets/example.yml

输出控制台 URL 与本次启动的 token；服务只绑定 127.0.0.1。

容器（单进程）

docker build -t agentos .
docker run --rm -p 127.0.0.1:8787:8787 \
  -v "$PWD/.agentos-docker:/app/.agentos" \
  --env-file .env \
  agentos

镜像内启动 serve --web --host 0.0.0.0；token 门禁仍对每个 /api/* 生效。 数据卷只有一个：/app/.agentos。

flowchart LR U[浏览器] -->|127.0.0.1:8787| D[Docker: agentos] D --> S[serve --web] S --> W[静态控制台] S --> A[REST + SSE] A --> K[内核 · 工具 · 模型 · 知识] K --> V[(".agentos 卷
sessions.db / workspaces / logs")]
当前没有"net 容器 + agent 容器"的拆分编排。Dockerfile 是单镜像单进程； 两容器方案需要新增：跨进程会话协议、共享 ledger 或 RPC、鉴权传递。属于新架构，不是配置项。

变量作用
AGENTOS_WEB_TOKEN固定 Web token（默认每次启动随机）

AGENTOS_ENV环境标签；tool manifest 的 envRouting 消费
AGENTOS_DEEPSEEK_* 等模型租约（变量名由 model manifest 指定）

10 降级与故障恢复

故障行为
工具 provider 缺凭证/缺变量该 provider 缺席 + ⚠ 告警，其余正常启动（环境错误不拖垮整体）
manifest 说谎（schema/引用）fail loud，拒绝启动——配置谎言不是部署状态
模型端点不健康alias 内 fallbackChain → 跨 manifest fallbackModels；结果卡片标 model-fallback
工具缺失错误 subtype tool-missing，渲染可行动卡片
门禁拒绝subtype gate-denied，落审计
网络错误subtype network，可重试提示
SSE 断线客户端重新回放 messages 再开流；服务端每 15s keepalive
进程崩溃重启时 sweep running 行；工作流恢复按 ledger 指针
