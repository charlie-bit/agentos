0. 一句话定位

AgentOS 是一个 model-agnostic 的 agent 平台。
一个内核（Claude Agent SDK）跑 agent 循环；profile / bundle / patch 描述业务；native tool / MCP tool / skill / agent 统一成 tool；control plane 提供观测、治理、审计、预算；Web 是唯一入口。

它不是：meta-harness（不跑 Claude Code / Codex / OpenHands 这类第三方 agent）、不是配置标准（不做公开 conformance）、不是跨运行时（同一份配置不追求在 LangGraph/DSH 上跑）、不是企业 SaaS（4A/多租户只留接口，不做运营面）。

两个直接回答

"跨运行时可移植"是什么意思？ 同一份 agent 定义能在不同 runtime（Claude SDK / DSH / LangGraph）上执行。DSH 的契约绑定 Cordis（只在 DSH 内有效）；OpenHands 用 ACP 把第三方 agent 装进来。我们不追求这个：我们的可移植性是"模型可换 + 工具走 MCP"，不是"配置跨 runtime"。

"要不要对齐 OpenHands 的平台方向？" 对齐它的 control plane / 沙箱后端 / Web UX / 对外 MCP；不对齐它"跑 Claude Code / Codex / OpenHands"的 agent 聚合模式——我们跑的是 model。

Model 层怎么做到"完全可切换"

这是你点名要的设计，单独说清楚：

  1. 内部只认一种 wire format：Anthropic Messages。因为 loop 是 Claude SDK，换 wire 等于换 loop，代价最大。
  2. 每个 vendor 一个 dialect：只做三件事——解析 channel（baseUrl/auth 只从 env 名取）、健康探测、alias→model。现有 anthropic-compat、bedrock 保留。
  3. OpenAI-compat 走 translation gateway：把 OpenAI Chat Completions 翻译成 Anthropic Messages（含流式、tool calls、stop、usage）。不放进 loop，放在模型层的边界上。
  4. 能力位 + 启动协商：每个模型声明 tools / parallel tools / streaming / structured output / vision / thinking / caching / context window / max output。启动时校验，缺关键能力就 fail fast，不静默降级。
  5. 探测不是 liveness：/v1/models 只证明端点活着；真正的探测是跑一次最小 tool-call smoke，证明这个模型能驱动 agent。
  6. 成本与预算：单价表进 manifest；每次请求记账；session/agent/tenant 三级预算硬停。
  7. 测试矩阵：每个 dialect × 每个能力位都有 contract test + cassette 回放，CI 阻断。

3. 三个必须先落地的设计

3.1 Desktop 之外的会话持久化

  • 事件日志是事实源，sqlite 只是索引；模型看到的一切必须能从日志重建。
  • checkpoint 放在 turn 边界；resume 从最近 checkpoint 继续；fork 从任意 turn 分叉。
  • 大结果落盘，日志只存指针；compaction 也是事件，不是覆盖写。
  • 崩溃恢复靠启动扫描，不靠进程内状态。

3.2 沙箱隔离

分四档，按部署选择，声明在 tool manifest 里：

档做法适用
T0fsRoots 路径 allowlist本地单用户默认
T1进程隔离（bwrap/Landlock/Seatbelt）本地多工具
T2每会话容器团队/多租户
T3远程沙箱云部署

默认拒绝；未声明的工具启动时告警；密钥只在执行时注入。

3.3 模型切换

见第 1 节"Model 层怎么做到完全可切换"。一句话：loop 只见 Anthropic wire，vendor 差异全部收在 dialect + gateway + capability 协商里。

4. 验收口径

  • P0 完成：换 3 个模型（Anthropic 兼容、Bedrock、OpenAI-compat）跑同一个角色，工具调用与流式一致；会话可 resume。
  • P1 完成：subagent + teams + group chat 可跑；workflow 支持分支/并行/checkpoint；web 能看到 trace、成本、审计。
  • P2 完成：沙箱 T0–T2 可选；eval 有 golden set 与回归门禁；单进程部署 + compose 一键起。
200 点 = 200 个可独立验收的 PR 切分。每点只写"做什么/怎么做/对齐什么"，实现细节留给各自的 issue。
